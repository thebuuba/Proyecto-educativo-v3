# Módulo Profile

**Responsabilidad:** Perfil personal del usuario autenticado.

| Método | Ruta | Auth | Descripción |
|--------|------|------|-------------|
| GET | `/profile` | JWT | Perfil propio (id, email, fullName, avatarUrl, phone) |
| PATCH | `/profile` | JWT | Actualiza nombre completo, teléfono y avatar; compatible con el formulario anterior |
| GET | `/profile/settings` | JWT | Identidad, preferencias, contexto académico y métricas reales |
| PATCH | `/profile/settings` | JWT | Guarda datos personales y preferencias en una transacción |
| POST | `/profile/avatar` | JWT | Foto propia multipart (`file`), PNG/JPEG/WebP hasta 2 MiB |
| DELETE | `/profile/avatar` | JWT | Quita la foto y su referencia almacenada |
| GET | `/profile/avatar` | JWT | Imagen privada del usuario actual, respuesta binaria sin caché |

Los ajustes se almacenan en `user_profile_settings`, relación única con `app_users`. Se consultan por identidad autenticada y escuela. Los datos institucionales, roles y correo son de solo lectura en ajustes; las métricas sin registro se devuelven como `null`, distinto de cero.

La fecha de nacimiento es civil (`YYYY-MM-DD`); la zona horaria IANA se usa para fechas de cuenta. Español es el único idioma disponible actualmente. La completitud mide presencia de datos, no verificación de teléfono ni de correo.

Las fotos se guardan en el bucket privado `profile-avatars`; el cliente nunca aporta una ruta de objeto. Las mutaciones bloquean la fila del usuario, confirman la referencia antes de limpiar el archivo anterior y preservan la foto previa ante errores de subida o persistencia. La ruta `/api/v1/profile/avatar?v=<uuid>` es propia de la sesión actual, no permite elegir otro usuario. La configuración de Supabase Storage debe estar disponible en el servidor y la migración nueva aplicada en el entorno correspondiente.
